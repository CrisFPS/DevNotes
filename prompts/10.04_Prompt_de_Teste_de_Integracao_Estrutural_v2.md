# Prompt estrutural v2 — decisões reais das rotas

Mesmo critério do prompt anterior, com o código dos desvios e o oráculo
corrigido depois da execução da v1. Trechos fiéis às rotas do DevNotes.

```text
Papel: especialista em teste de integração caixa-branca, focado em
cobertura de decisões das rotas FastAPI do DevNotes Local.

Critério: cada desvio abaixo precisa de um caso. Não use códigos de API JSON
genéricos. A execução da versão anterior mostrou este erro de oráculo:
- POST /content/new seguido pelo TestClient devolveu 200, não 201.
  O status da rota, sem seguir redirecionamento, é 303.
- POST /upload com .xlsx devolveu 400 em HTML, não 406.
- GET /content/99999 devolveu HTML; resposta.json() lançou JSONDecodeError.
- POST /content/{id}/delete devolveu 200 com o cliente seguindo o redirecionamento,
  não 204.

Ferramenta: pytest, TestClient, fixtures client, db e upload_dir.
Para observar 303, chame follow_redirects=False.

Desvios a cobrir, extraídos das rotas:

process_upload:
- save_upload sem exceção: cria conteúdo e responde RedirectResponse 303.
- save_upload lança exceção: TemplateResponse upload.html com status 400.
- validate_extension rejeita extensão fora da lista (HTTPException 400).
- len(raw) > MAX_SIZE_BYTES rejeita; len(raw) == MAX_SIZE_BYTES aceita.
  No teste, substitua MAX_SIZE_BYTES por 8 para exercitar a fronteira
  sem gravar 12 MB. A regra de produção continua sendo 12 MB.
- title.strip() vazio: o título persistido é o nome original do arquivo.
- title.strip() preenchido: o título persistido é o informado.
  O nome original continua visível nos metadados do arquivo.

detail:
- svc.get devolve None: 404.html com status 404.
- svc.get devolve item: detail.html 200 com <pre><code> e o texto.

delete_content:
- item ausente: RedirectResponse /content 303.
- item presente: delete e redirecionamento; a busca não encontra mais o texto.
- svc.delete lança Exception: error.html 500 com
  "Não foi possível excluir o conteúdo".

update_content:
- item ausente: RedirectResponse /content 303.

list_content / list_page:
- page < 1 é tratada como página 1.
- page acima do total ainda exibe o item existente.

do_search:
- query vazia não usa FTS MATCH; aplica só os filtros preenchidos.
- is_business_rule verdadeiro restringe às regras de negócio.
- category, language, system e domain preenchidos filtram em conjunto.

Cada teste deve nomear, na docstring, o desvio coberto.
Não gere casos de autenticação nem de Selenium.
```
